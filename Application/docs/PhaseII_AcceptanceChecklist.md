# Phase II Acceptance Checklist

## Landing page

- [ ] Application title displays as Client Management System.
- [ ] Center tiles display New Project, New Client, and Dashboard.
- [ ] Each tile navigates to the correct page.
- [ ] File menu includes New Project, New Client, Dashboard, and Admin.

## New Project

- [ ] Client dropdown is populated from `tClient` through `usp_Client_GetTop25`.
- [ ] User group dropdown is populated from `tUserGroup` through `usp_UserGroup_GetTop25Groups`.
- [ ] Project type dropdown is populated from `tProjectType` through `usp_ProjectType_GetAll`.
- [ ] Project name is required.
- [ ] Revenue supports numeric values.
- [ ] Renewal date supports a nullable date.
- [ ] Created date is not manually editable and is generated by SQL.
- [ ] Save writes through `usp_Project_Insert` or `usp_Project_Update`.

## New Client

- [ ] Top 25 existing clients are displayed.
- [ ] Client can be created.
- [ ] Existing client can be selected and edited.
- [ ] Status values are populated from `tStatus`.
- [ ] Active status is the default for new clients.
- [ ] Segment values are populated from `tSegment`.
- [ ] Account executive and analytics lead dropdowns are populated from `tUser`.
- [ ] Client can be set inactive through `usp_Client_SetStatus` with status code `I`.

## Admin tabs

- [ ] Server tab restricts server choices to the approved list.
- [ ] Server settings are encrypted at rest.
- [ ] Users tab supports add, remove, copy, edit, save, and cancel.
- [ ] User Role tab supports add, remove/deactivate, edit, save, and cancel.
- [ ] UserGroup tab supports creating a group and assigning BMS users/roles.
- [ ] Project Types tab supports add, remove, edit, save, and cancel.
- [ ] Segment tab supports add, remove, edit, save, and cancel.
- [ ] Status tab supports add, modify, delete, save, and cancel.
- [ ] Administrative list boxes display 25 visible rows.
- [ ] Administrative tab panels use the same size and shape.

## Security

- [ ] No SQL credentials are hardcoded in source code.
- [ ] No connection string is stored in `appsettings.json`.
- [ ] Encrypted settings file is excluded from source control.
- [ ] Application identity has execute-only stored procedure permissions.
- [ ] Admin pages are protected before production deployment.
